===============================================================================
0. Purpose
===============================================================================

This specification serves as the bridge between finalized combat design specs
and Unity implementation. It provides:

- Cross-spec audit results with fixes applied and issues flagged
- AP economy simulations validating PvP fairness
- Species pool validation confirming exclusive-move compliance
- Data-driven drop table structures ready for ScriptableObject conversion
- UI metadata schemas for Chainling and modifier display
- A phased Unity testing plan with debug hooks

DESIGN PRINCIPLES:
- Systems-first: all data structures map to reusable ScriptableObjects
- Data-driven: combat logic consumes config data, never hard-codes content
- Deterministic: all combat resolution is seed-reproducible for PvP replay
- Observable: every combat event is logged for debugging and balancing

1.3 Design Ambiguities — ALL RESOLVED (v1.2 lockdown)

AMBIGUITY A: Cooldown Mechanics in Baseline Inscriptions — ✓ RESOLVED

DECISION: Option A — Reframe as "Recharge" mechanic using ConsumedStatus.
IMPLEMENTED IN: COMBAT_02C v1.2 §1.2

After use, the engine applies InscriptionRecharging(N) ConsumedStatus to the
specific inscription instance. Duration decrements at End of Turn. While active,
the inscription cannot be selected. This is a status-based solution consistent
with the status-driven architecture — NO separate cooldown timer system.

Inscriptions using Recharge:
- Extend Protocol (Node): Recharging(3)
- AP Boost (Typeless): Recharging(3)
- Gecko Guard (Gilarime exclusive): Recharging(999) — once per battle
- Fox Feint (Kitsauto exclusive): Recharging(999) — once per battle

AMBIGUITY B: Streamlined Flow AP Cost Reduction — ✓ RESOLVED

DECISION: Option A — Keep as intentional baseline exception.
IMPLEMENTED IN: COMBAT_03A1 v1.2.1 (lockdown note on Streamlined Flow)

Streamlined Flow (Compressed passive) is an accepted baseline exception to the
"no AP cost reduction" modifier rule. The ban in Spec 05 applies to MODIFIERS only.
Counterbalances: -1 Def stage + HP > 70% threshold.
TESTING FALLBACK: If abuse is detected, apply Option B (AP Refund cannot trigger
on moves whose AP cost was reduced by a passive).

AMBIGUITY C: Stage Change Guardrails — ✓ RESOLVED

DECISION: Three-tier guardrail system.

2. AP Economy Simulation
===============================================================================

2.1 Baseline AP Flow (No Modifiers)

Turn structure per 02A §3 and 02C §1:
- Start of Turn: +3 AP (baseline, always)
- Action Phase: spend AP on inscriptions (1-3 AP each)
- End of Turn: status AP effects resolve (Pumped, Drained, MEV Extracted, etc.)

STANDARD TURN ECONOMY:
| AP Available | Possible Actions                              | AP Remaining |
|--------------|-----------------------------------------------|--------------|
| 3            | One 3-AP move                                 | 0            |
| 3            | One 2-AP move + one 1-AP move                 | 0            |
| 3            | Three 1-AP moves                              | 0            |
| 3            | One 2-AP move (save 1 AP)                     | 1            |
| 3            | One 1-AP move (save 2 AP)                     | 2            |

KEY INSIGHT: Players always have exactly 3 AP to spend (plus carryover).
With an average inscription cost of ~1.8 AP, players get ~1.6 actions per turn.
Banking AP for expensive moves (3-4 AP) requires skipping a turn of damage.

2.2 AP Refund Impact Analysis

Modifier §3.1 provides AP refund chances:

| Modifier | Rarity    | Refund Chance | Expected AP/Use |
|----------|-----------|---------------|-----------------|
| §3.1-a   | Common    | 5-10%         | 0.075           |
| §3.1-b   | Uncommon  | 10-15%        | 0.125           |
| §3.1-c   | Rare      | 15-20%        | 0.175           |

SCENARIO: Rare refund modifier on a 2-AP move, used once per turn.
- Per turn: 0.175 expected AP saved
- Over 10 turns: 1.75 extra AP = ~1 extra action over the course of a battle
- AP efficiency gain: 5.8% per turn

VERDICT: BALANCED. The refund is modest and probability-based. Even at Rare tier,
it provides roughly 1 free action every 6 turns. Not enough to distort tempo.

2.3 Bonus Action Impact Analysis

Modifier §3.2 provides bonus action chances:

| Modifier | Rarity    | Chance  | Effect                           | Expected Actions/Turn |
|----------|-----------|---------|----------------------------------|----------------------|
| §3.2-a   | Rare      | 8-12%  | Repeat same move (no AP)         | 0.10                 |
| §3.2-b   | Epic      | 15-20% | Auto-use random typeless move    | 0.175                |
| §3.2-c   | Legendary | 12-15% | Auto-use random equipped move    | 0.135                |

CHAINING RULE: Bonus actions CANNOT trigger other bonus action modifiers.
Maximum 1 bonus action per turn per modifier trigger.

10-TURN IMPACT:
- §3.2-a (Rare): ~1 free repeated move over 10 turns
- §3.2-b (Epic): ~1.75 free typeless moves over 10 turns
- §3.2-c (Legendary): ~1.35 free moves over 10 turns

VERDICT: BALANCED. Even the strongest bonus action (§3.2-b Epic) provides less
than 2 free actions over a 10-turn battle. The anti-chaining rule prevents
exponential action spirals. Legendary rarity gates the strongest version.

2.4 AP-Denial Strategy Analysis (PvP)

WORST-CASE SCENARIO: Bot-type Kitsauto with full AP denial kit.

Available AP denial tools:
- MEV Extract [UTIL][APMAN]: 2 AP — steal 1 AP/turn for 2 turns
- Thread Lock [UTIL][APMAN]: 2 AP — target cannot gain AP next turn
- AP Drain [UTIL][APMAN]: 2 AP — target loses 1 AP (25% chance steal)

TURN-BY-TURN SIMULATION (Kitsauto vs. Opponent, both start at 3 AP):

Turn 1: Kitsauto (90 Speed, acts first)
  - Action: MEV Extract (2 AP) → 1 AP remaining
  - Target: Has 3 AP, acts normally. End of turn: -1 AP from MEV = effective +2 net
  - Kitsauto End: +1 AP from MEV steal

Turn 2: Kitsauto (1 + 3 + 1 MEV steal = 5 AP)
  - Action: Thread Lock (2 AP) → 3 AP remaining
  - Action: Baseline Jab (1 AP) → 2 AP remaining, 40 power chip
  - Target: Acts with remaining AP. End of turn: -1 AP from MEV (last turn)
  - Thread Lock takes effect NEXT turn.

Turn 3: Kitsauto (2 + 3 = 5 AP)
  - Target: +0 AP gain (Thread Lock blocks baseline +3). Has only carryover AP.
  - If target spent all AP on turn 2: target has 0 AP. CANNOT ACT.
  - Kitsauto: Free to set up or deal damage with 5 AP.

ANALYSIS:
- Total AP spent on denial: 4 AP over 2 turns (MEV + Thread Lock)
- Total AP denied from opponent: ~5 AP (2 turns of -1 MEV + 1 turn of -3 Thread Lock)
- Net advantage: ~1 AP over 3 turns PLUS a free damage turn on turn 3
- This IS a strong strategy but costs Kitsauto 2 full turns of damage output.

COUNTERPLAY:
1. Cleanse (1 AP) removes MEV Extracted
2. AP Reserve (Staked, 0 AP) banks AP before Thread Lock turn
3. Switch Chainling — new entrant has fresh AP and no MEV/Thread Lock
4. Encrypted Seal (debuff immunity) prevents MEV application
5. Priority moves (Baseline Jab) can be used with saved 1 AP even under pressure
6. Double-or-Nothing (Meme passive) has AP drain immunity on lose

VERDICT: STRONG BUT COUNTERABLE. The AP denial combo requires 2 turns of setup
with zero damage output. Against prepared opponents (Cleanse, AP Reserve, swaps),
it underperforms compared to just dealing damage. Thread Lock is the key piece;
monitor for abuse in playtesting. If needed, reduce to "target gains 1 AP instead
of 3 next turn" (soft lock instead of hard lock).

2.5 Streamlined Flow Exception Analysis

Compressed passive: "all moves -1 AP cost (min 1), -1 Def stage" while HP > 70%.

IMPACT MODELING:

Without Streamlined Flow (standard):
  3 AP → 2-AP move + 1-AP move = 2 actions
  
With Streamlined Flow:
  3 AP → (2-1=1 AP move) + (2-1=1 AP move) + (1=1 AP move) = 3 actions

EFFECTIVE AP MULTIPLIER: ~1.5x actions per turn (3 vs 2 actions)

RISK FACTORS:
- -1 Def stage is permanent while equipped (increases damage taken by ~33%)
- HP > 70% threshold means any significant hit turns off the passive
- At Level 50 with ~200 HP: a single 70-power typeless hit deals ~35-45 damage
  (17-22% HP), meaning 2 hits turn off Streamlined Flow
- Against burst strategies: completely useless after turn 1-2

COMBINED WITH AP REFUND (§3.1-c Rare):
- 3 actions per turn × 17.5% refund chance per action = 0.525 expected AP/turn
- Over 10 turns: 5.25 extra AP = ~2.6 extra actions (IF HP stays above 70%)
- Realistic estimate (HP drops below 70% by turn 4): 2.1 extra AP total

VERDICT: STRONG BUT FRAGILE. The glass-cannon tradeoff (-1 Def, HP threshold)
makes Streamlined Flow high-risk. In PvP, opponents can focus-fire the
Compressed Chainling to disable it. No action needed; monitor in testing.

2.6 PvP Fairness Assessment

OVERALL AP ECONOMY HEALTH:

| Metric                                  | Value       | Assessment |
|-----------------------------------------|-------------|------------|
| Baseline AP per turn                    | 3           | Fixed      |
| Max AP refund per turn (expected)       | 0.175       | Marginal   |
| Max bonus actions per turn (expected)   | 0.175       | Marginal   |
| Max AP denial per turn (dedicated)      | 3 (Thread Lock) | Strong |
| Streamlined Flow effective gain         | +1 action   | Conditional|
| AP manipulation tools available         | 37 inscriptions | Diverse |

KEY FINDINGS:
1. AP refund and bonus action rates are too low to create runaway advantage.
2. AP denial is strong but requires heavy investment (multiple AP-denial moves).
3. The most dangerous combo is Thread Lock + MEV Extract, but it costs 4 AP
   and 2 turns of zero damage, which is fair given the payoff.
4. Streamlined Flow is the strongest single AP efficiency tool but is
   self-limiting via the Def penalty and HP threshold.
5. No combination of modifiers and inscriptions creates an infinite AP loop.

4.1 ScriptableObject Schema: DropTable

```
[CreateAssetMenu(menuName = "Combat/DropTable")]
DropTableSO {
  id: string                     // e.g., "standard_levelup", "entangled_levelup"
  displayName: string            // e.g., "Standard Level-Up"
  
  inscriptionChance: float       // Chance to receive an inscription (0.0-1.0)
  consumableChance: float        // Chance to receive a consumable
  currencyChance: float          // Chance to receive currency/tokens
  // NOTE: These three must sum to 1.0
  
  rarityWeights: RarityWeight[]  // Weighted distribution when inscription drops
  
  modifierChance: float          // Independent chance for modifier drop (0.0-1.0)
  modifierRarityWeights: RarityWeight[]  // Distribution for modifier rarity
}
```

```
[Serializable]
RarityWeight {
  rarity: InscriptionRarity      // Enum: Common, Uncommon, Rare, Epic, Legendary, Mythic
  weight: float                  // Probability (must sum to 1.0 across all entries)
}
```

```
enum InscriptionRarity {
  Common,     // Gray   #9E9E9E
  Uncommon,   // Green  #4CAF50
  Rare,       // Blue   #2196F3
  Epic,       // Purple #9C27B0
  Legendary,  // Orange #FF9800
  Mythic      // Red    #F44336
}
```

4.3 Combined Level-Up Resolution Flow

When a Chainling gains a level, the following occurs:

```
function ResolveLevelUp(chainling, dropTable):
  seed = GenerateDeterministicSeed(chainling.id, chainling.level)
  rng = SeededRNG(seed)
  
  // Step 1: Determine primary reward type
  roll = rng.NextFloat()
  if roll < dropTable.inscriptionChance:
    reward = ResolveInscriptionDrop(chainling, dropTable, rng)
  elif roll < dropTable.inscriptionChance + dropTable.consumableChance:
    reward = ResolveConsumableDrop(rng)
  else:
    reward = ResolveCurrencyDrop(rng)
  
  // Step 2: Independent modifier roll
  modRoll = rng.NextFloat()
  if modRoll < dropTable.modifierChance:
    modReward = ResolveModifierDrop(chainling, dropTable, rng)
    ApplyModifier(modReward)
  
  // Step 3: Check learnable pool
  // If the chainling reaches a learnable-pool level threshold,
  // grant the next inscription from their curated learnable list.
  if IsLearnableLevel(chainling):
    GrantLearnableInscription(chainling)
  
  return reward
```

```
function ResolveInscriptionDrop(chainling, dropTable, rng):
  // Step 1: Determine rarity
  rarityRoll = rng.NextFloat()
  rarity = SelectRarity(dropTable.rarityWeights, rarityRoll)
  
  // Step 2: Build eligible pool
  pool = []
  pool.AddRange(GetTypedInscriptions(chainling.primaryType, rarity))
  if chainling.secondaryType:
    pool.AddRange(GetTypedInscriptions(chainling.secondaryType, rarity))
  pool.AddRange(GetTypelessInscriptions(rarity))
  
  // Meme exception: Meme types can access ALL typed inscriptions
  if chainling.primaryType == Meme or chainling.secondaryType == Meme:
    pool.AddRange(GetAllTypedInscriptions(rarity))
  
  // Remove duplicates (already equipped)
  pool.RemoveWhere(i => chainling.HasInscription(i))
  
  // Step 3: Select random inscription from pool
  if pool.IsEmpty():
    return FallbackReward()  // Currency or consumable if pool exhausted
  
  return pool[rng.NextInt(pool.Count)]
```

4.4 Pool Exhaustion Handling

With 184 baseline moves and a max of 16 slots, pool exhaustion is unlikely
for individual Chainlings. However, the system should handle edge cases:

| Scenario                          | Resolution                           |
|-----------------------------------|--------------------------------------|
| No inscriptions of rolled rarity  | Re-roll rarity (adjacent tier first) |
| All eligible inscriptions equipped| Grant currency/consumable instead    |
| Rarity re-roll exhausted          | Grant Common typeless inscription    |
