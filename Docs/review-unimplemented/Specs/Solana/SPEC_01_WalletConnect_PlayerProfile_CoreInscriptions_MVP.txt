SPEC 01 - Wallet Connect + Player Profile + Chainbound Asset Inventory (Legacy MVP Updated)

Status: legacy planning document updated to the current canonical taxonomy.
Canonical source: Docs/Specs/Solana/CHAINBOUND_SOLANA_ASSET_TAXONOMY.md
==================================================================================

Goal (hackathon MVP)
-------------------
From Main Menu:
1) Connect wallet (PSG1 integrated + Phantom/Solflare/Jupiter/etc.)
2) Create/load PlayerProfile PDA
3) Read player inventory according to the current Chainbound taxonomy:
   - Ordinals are game PDAs.
   - Inscriptions are compressed NFTs/cNFTs.
   - Runes are Metaplex Core NFTs.
   - Cosmetics are Metaplex Core assets under Chainbound Cosmetics.
4) Save minimal progress: win/loss, chainling storage snapshot pointer(s), progression flags

NOTE: PvP wagering escrow + staking can be stubbed for MVP (only reserve “lock flags” and interfaces).

Architecture (authoritative split)
----------------------------------
On-chain (authoritative)
- PlayerProfile PDA (keyed by wallet)
- Ordinals = game PDAs
- Inscriptions = compressed NFTs/cNFTs
- Runes = Metaplex Core NFTs
- Cosmetics = Metaplex Core assets under Chainbound Cosmetics
- (Optional) ChainlingAccount PDAs for captured chainlings (recommended for MVP)

Off-chain (derived/indexed; optional for MVP)
- Supabase or local cache for fast menus; never the source of truth for ownership

On-chain data model (MVP)
-------------------------
PlayerProfile PDA (minimum fields)
- owner: Pubkey
- schema_version: u16
- created_at_slot: u64
- wins: u32
- losses: u32
- last_known_scene_id: u32 (optional)
- last_known_pos: (i16,i16,i16) quantized (optional)
- active_party_chainling_ids: [u64; N] (optional small N, e.g., 3)

Principle: store only what is needed for submission demo. Everything else can be local/off-chain for now.

Legacy note: this spec previously described Inscriptions as Metaplex Core NFTs.
That model is retired. Current runtime code treats Inscriptions as cNFTs and Runes
as Metaplex Core NFTs.
----------------------------------
Rune and cosmetic Core metadata schema (game-specific JSON)
- inscription_id
- rarity (C/U/R/E/L/M)
- type / element (if applicable)
- modifiers[] (or encoded form)
- schema_version
- minted_at_slot
- source_context (optional: encounter zone id / capture id)

Rarity semantics should follow AcquisitionRarity spec (rarity affects complexity + mods; not raw power).

Unity implementation requirements
---------------------------------
Services (required)
- WalletService (Solana.Unity-SDK)
- ProfileService (derive PDA, create/read/update)
- Current Inscription inventory service:
  - fetch/verify cNFT Inscriptions through the Bubblegum/DAS path
  - filter for Chainbound inscription metadata
  - parse trusted metadata -> InscriptionDef
- Legacy CoreInscriptionService:
  - migration-only surface for retired Core Inscription assets
  - must not be used for current Inscription mint/read flows

Main Menu UX flow
-----------------
States:
- Disconnected -> Connecting -> Connected
- Profile: Missing -> Creating -> Ready
- Inventory: Loading -> Ready

Persistence
-----------
- Cache last wallet pubkey + profile address
- Persist pending tx signatures (create profile, updates) and re-check on resume

Acceptance criteria (MVP)
-------------------------
- Connect wallet from Main Menu and display pubkey
- If no profile: create profile PDA with a single signed tx; confirm finalized
- Load profile and show wins/losses
- Load cNFT inscription inventory list (IDs + rarity/modifier at minimum)
- Load Core rune inventory list where Tier 3 Rune ownership is needed
- No per-frame RPC; refresh only on UI open and after tx finalize

Out of scope (explicitly post-hackathon)
----------------------------------------
- PvP wagering escrow settlement
- Full NFT staking loops / token staking loops
- Full off-chain indexing pipeline
