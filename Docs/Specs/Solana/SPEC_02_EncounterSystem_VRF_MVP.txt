SPEC 02 — Encounter System + VRF (Chainlings + IVs + Mutations + Rare Inscription Rolls)
===================================================================================================

SUPERSEDED (2026-08): Live wild encounters use local seeded EncounterRollService +
EncounterZoneSO / EncounterAreaSO (no VRF). Capture is profile-first via Supabase
(profile_capture_wild). Keep this file for historical reference only. Solana/VRF
remains for vending/mint paths, not wild encounter generation.

Goal (hackathon MVP)
-------------------
When player enters a trigger collider region:
1) Start encounter request (VRF)
2) Resolve encounter result (species + IVs + mutation flags + rare inscription roll inputs)
3) Load BattleScene with encounter payload
4) After battle:
   - if player wins/captures: persist captured chainling (PDA) + mint 1 inscription NFT (see SPEC 03)
   - respawn player at pre-encounter position
   - if defeated: respawn at home (fixed respawn transform)

Determinism + verifiability
---------------------------
Use MagicBlock VRF for encounter RNG:
- Program CPI’s into VRF to request randomness
- VRF verifies proof and callbacks into your program to consume randomness
- Encounter result is derived deterministically from the stored randomness

On-chain data model (MVP)
-------------------------
EncounterRequest PDA (recommended)
- owner: Pubkey
- seed_context: { zone_id, encounter_table_id }
- status: Pending | Fulfilled | Consumed
- vrf_request_id
- randomness: [u8; 32] (set on callback)
- created_at_slot

Encounter result derivation (deterministic)
------------------------------------------
From randomness derive:
- species_id via zone table weights
- ivs[] via modulo mapping
- mutated_type_flag via threshold
- entangled_flag (bootleg) via threshold
- inscription_candidate_seed (a derived number used later to pick the “equipped inscription” after capture)

Rarity roll tables must match AcquisitionRarity spec (entangled boosts Rare+ odds).

VRF program flow (must-have states)
-----------------------------------
Encounter state machine:
- RequestingRandomness
- PendingRandomness (await callback)
- Ready (randomness stored)
- Consumed (encounter finalized; payload issued)

Unity scene integration
-----------------------
World trigger region
- EncounterTrigger component:
  - zoneId
  - encounterTableId
  - cooldownSeconds / minStepsBetweenEncounters
  - OnPlayerEnter() starts encounter pipeline

Encounter pipeline (client)
1) Save current world return context:
   - sceneId
   - playerPosition
   - playerRotation
2) Call on-chain “RequestEncounterRandomness” (tx)
3) Poll EncounterRequest PDA until status == Fulfilled (debounced; PSG1 safe)
4) Build EncounterPayload:
   - species, ivs, types, flags, and inscription_candidate_seed
5) Load BattleScene with payload

Post-battle return (client)
- If player won:
  - Grant XP: per-enemy KO XP (awarded during battle) + completion bonus (awarded on encounter resolution). See ECONOMY_01 §Battle XP Rewards.
  - Allow capture attempt (SPEC 03)
- If player lost:
  - set respawn to Home
- Restore world scene and teleport to saved position (or Home)

Acceptance criteria (MVP)
-------------------------
- Enter trigger zone -> encounter starts reliably
- Encounter result is VRF-backed (request + callback consume)
- BattleScene receives deterministic payload
- After battle: returns to exact pre-encounter location OR Home on defeat
- Encounter cooldown prevents rapid retriggers

Out of scope (post-hackathon)
-----------------------------
- Fully-featured market acquisition sources
- Full on-chain mint of every encountered chainling (we use PDA first)
