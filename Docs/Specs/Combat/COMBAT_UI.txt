COMBAT_08_CombatUI_v1.0

===============================================================================
0. Purpose
===============================================================================

Defines the complete Combat UI layout, component hierarchy, data bindings,
interaction flows, and visual language for the battle system. This spec bridges
the data schemas in Spec 07 (Â§5) to concrete Unity UI implementation.

AESTHETIC REFERENCE: Cassette Beasts (Bytten Studio, 2023)
- Clean, minimal HUD with information density on demand
- Pixel-art-inspired 3D models on stylised arena backgrounds
- Bottom-anchored action panel for move selection
- Top-anchored enemy info panels
- Status icons as small badges beneath HP bars
- Type indicators using distinct colour-coded icons
- Pop-up text for effectiveness, crits, and AP changes
- No visible turn-order bar; speed determines action priority

ADAPTATION FOR CHAINBOUND:
- Moves (up to 16 slots) replace CB's 8-slot sticker system
- Persistent AP pool (cap 10, +2/turn) replaces CB's per-turn AP
- Modifier badges on moves add visual complexity
- Chemistry reactions (coatings, transmutation) need clear feedback
- Combat log panel for deterministic replay support
- Type chemistry feedback is richer than CB's simple effectiveness

DESIGN PRINCIPLES:
- Minimal by default, detailed on demand (progressive disclosure)
- All combat-relevant state visible without menus during action resolution
- Consistent with systems-first architecture (all UI binds to data, not logic)
- Deterministic: every UI state is reconstructable from combat log
- Accessible: colour is never the sole differentiator; use icons + text

1.1 Battle Format

Default format: 2v2 (Player + Partner vs Enemy A + Enemy B)
- Mirrors Cassette Beasts' 2v2 partner battle structure
- Player controls their own Chainling; partner is AI-controlled or co-op
- Wild encounters may be 2v1 or 2v2
- Boss encounters may be 2v1 (boss has boosted stats)

1.2 Camera

- Default: Behind player team, slightly elevated, looking toward enemies
- On action: camera smoothly shifts to focus on attacker â†’ target
- On chemistry reaction: brief camera shake + zoom on affected Chainling
- On KO: slow-motion final hit, camera pulls back

2.3.2 HP Bar
-------------------------------------------------------------------------------

- Width: 200px (scalable)
- Height: 12px
- Fill direction: left to right
- Color transitions: smooth lerp based on HP percentage
  - >50%: Green (#4CAF50) â†’ Yellow (#FFEB3B) at 50%
  - 25-50%: Yellow (#FFEB3B) â†’ Red (#F44336) at 25%
  - <25%: Red (#F44336), bar pulses gently
- Damage preview: when hovering an attack move, show a translucent
  damage preview region on the target's HP bar (estimated damage range)
- Numeric text: right-aligned, "[current]/[max]"
- Animation: smooth interpolation over 0.3s when HP changes

CB REFERENCE: Cassette Beasts uses a simple greenâ†’red HP bar with numeric
overlay. We match this but add the damage preview on hover.

2.3.4 Status Icon Strip
-------------------------------------------------------------------------------

- Position: below HP bar, left-aligned
- Max visible: 8 icons (scroll indicator if more)
- Each icon: 16x16px, type-coloured border if applicable
- Duration overlay: small number in corner (turns remaining)
- Class indicator: icon shape varies by status class
  - DurationStatus: clock icon overlay
  - ConsumedStatus: lightning bolt overlay
  - CounterStatus: numbered badge overlay
  - InstantStatus: (no icon, resolves immediately)

12. Animation & Timing Guidelines
===============================================================================

12.1 Turn Flow Timing

| Phase                    | Duration | Notes                          |
|--------------------------|----------|--------------------------------|
| Decision phase           | Untimed  | Player decides at own pace     |
| Turn order banner        | 1.5s     | Shows speed order, then fades  |
| Per-action (normal)      | 2.0s     | Attack animation + result      |
| Per-action (crit)        | 2.5s     | Extended with crit flash       |
| Per-action (multi-hit)   | 0.5s/hit | Each hit rapid, total at end   |
| Chemistry reaction popup | 2.5s     | Center screen card             |
| Status apply animation   | 1.0s     | Icon appears + brief text      |
| End of turn ticks        | 0.5s/ea  | DoT, AP regen, status expire   |
| KO animation             | 3.0s     | Slow-motion + faint animation  |

Total turn time (typical): 8-12s for 4 actions + resolution

12.2 Animation Priority

When multiple events happen simultaneously (e.g., damage + status apply + AP
change), queue them:
1. Damage number appears
2. HP bar animates
3. Status icon appears (0.3s delay)
4. Chemistry reaction card (if applicable) (0.5s delay)
5. AP change notification (after chemistry resolves)

12.3 Speed Controls

| Setting    | Multiplier | Use Case                    |
|------------|------------|-----------------------------|
| Normal     | 1.0x       | Default                     |
| Fast       | 2.0x       | Experienced players         |
| Instant    | Skip anim  | Testing / speedrun          |

Player can toggle speed in Settings or via hotkey (Space to toggle).

CB REFERENCE: CB has a similar speed-up option. Match the default pacing
to CB's comfortable rhythm, with options to accelerate.

17. Implementation Notes
===============================================================================

17.1 Data Flow

```
CombatEngine (logic)
    â”‚
    â”œâ”€â”€ publishes â†’ CombatEvent (action, damage, status, etc.)
    â”‚
    â””â”€â”€ updates â†’ BattleStateUIData (master UI state)
                      â”‚
                      â””â”€â”€ read by â†’ All UI Components
                                    (ChainlingInfoPanel, ActionPanel, etc.)
```

UI components NEVER modify combat state. They only READ from
BattleStateUIData and WRITE player input to ActionInput.

```
ActionInput {
  moveId: string?,
  targetId: string?,
  isSwap: bool,
  swapTargetId: string?,
  isFlee: bool
}
```

17.2 Event-Driven Updates

All UI updates are triggered by events, not polling:

```
CombatEventBus {
  OnTurnStart(turnNumber: int)
  OnActionResolved(entry: ActionQueueEntry)
  OnDamageDealt(breakdown: DamageBreakdownEntry)
  OnStatusApplied(target: string, status: StatusIconData)
  OnStatusExpired(target: string, statusId: string)
  OnChemistryReaction(reaction: ChemistryReactionData)
  OnAPChanged(chainlingId: string, oldAP: int, newAP: int)
  OnStageChanged(chainlingId: string, stat: string, oldStage: int, newStage: int)
  OnChainlingKO(chainlingId: string, killerMoveId: string)
  OnCoatingApplied(chainlingId: string, coatingType: ChainlingType)
  OnCoatingExpired(chainlingId: string)
  OnModifierTriggered(moveId: string, modifierSectionId: string)
  OnRechargeComplete(chainlingId: string, moveId: string)
  OnBattleEnd(result: BattleResult)
}
```

17.3 Object Pooling

The following UI elements should use object pooling for performance:
- Floating damage numbers (pool size: 20)
- Notification popups (pool size: 10)
- Combat log entries (pool size: 100)
- Status icons (pool size: 30)
